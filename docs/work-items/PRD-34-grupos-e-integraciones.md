# PRD-34 — Groups and integrations (.ics calendar feeds, Meet, Google import/export, group bridges)

- **Type:** PRD
- **Tier:** 2 — Roadmap (PRD v3 Part IV)
- **Priority:** P2
- **Status:** Backlog
- **Source:** PRD v3 **§28** (incl. §28.1 calendar, §28.2 Meet, §28.3 import, §28.4 build order).

## Problem / why

Coordinators already live in WhatsApp groups and Google Calendar. Convite must **plug in beside** them
(principle: "not a group chat", §2), not replace them. Two facts shape this: **WhatsApp Cloud API
cannot join groups** — strictly 1:1, do not attempt it (§28); and **Agenda is a calendar**, so the
highest-value integration is an **.ics subscribe URL** with zero setup (§28.1).

## Scope (in build order — §28.4)

**In:**
1. **.ics feeds (highest value, zero setup).** A subscribe URL pasted into Google Calendar surfaces
   jornadas, citas and departures alongside everything else, staying current forever — no consent
   screen, no tokens. **Feeds are per-person and scoped, never one shared calendar** (§28.1):
   coordinador → jornadas/envíos/citas for their region; verificador → citas they must arrange;
   proveedor → only their own citas; transportista → only their own runs. **Each URL is a secret tied
   to a membership and revoked on offboarding** (§29.6). **Discretion binds hardest here** — a feed
   syncs to a lock screen: titles carry **folio + type, never the person or condition** —
   ✓ «Cita 472 · Puerto Meluk · 9:00», ✗ «Teleconsulta medicina crónica — Rosalba Cuesta». Emit
   **fixed UTC−5 offsets** (Colombia has no DST), not floating times.
2. **Scheduled email of a spreadsheet, plus CSV and XLSX download** (Informes exports).
3. **Manual Meet links pasted into citas** (§28.2). **Meet is never the default** — the join method
   follows link quality (§27b.2); generating a Meet link for Docampadó is worse than useless. If a
   template carries the link, note Meta's extra rules for template URLs.
4. **«Conectar con Google» — one OAuth button (§28.4.4), all token machinery on our side:** read a
   Sheet, create Calendar events with Meet links, write evidence to Drive. **Partners must never see a
   client ID** (§28.1).
- **Group bridges needing no integration (§28):** a `wa.me` deep link pinned in the group (announce /
  belong), and **paste-ready summaries** a coordinator copies in (also cheaper once service messages
  bill from 1 Oct 2026). The group is for announcement; the 1:1 line is for the record.
- **Import ≥ export (§28.3):** reading a responses Sheet (assessments already on Google Forms;
  Herencia's volunteer signup) and a partera directory Sheet (ASOREDIPARCHOCÓ) is worth more than
  writing one. **Ask what exists before designing anything.**

**Out:**
- Any attempt to have the bot join a WhatsApp group (impossible, §28).
- **Drive-for-evidence** is deferred behind an explicit sharing-config gate (§28.4): Drive sharing
  defaults are a real risk with images of damaged houses — require explicit sharing config and **strip
  EXIF first** (§13). Do not enable Drive writes in this WI without that gate.

## Acceptance criteria

1. A per-person **.ics subscribe URL** works in Google Calendar; it is **scoped by role/region**, its
   titles carry **folio + type only** (never person/condition), and it emits **fixed UTC−5** times.
2. The .ics URL is a **membership secret** and is **revoked on offboarding** (coordinated with PRD-16
   §29.6).
3. Informes offers **CSV + XLSX download** and a scheduled-email export.
4. A coordinator can **paste a Meet link** into a cita manually; Meet is not auto-generated by default
   and is chosen only per §27b.2 link quality.
5. Group bridges exist: a pinned `wa.me` deep link and copy-paste-ready summaries; no attempt to join a
   group.
6. At least one **import** path (read a Google Sheet — partera directory or assessment responses) is
   supported; OAuth hides all client-ID/token machinery from the partner.
7. Drive-for-evidence remains **disabled** unless an explicit sharing config is set and EXIF is
   stripped.

## Dependencies

- **Calendar feed revocation** couples to **PRD-16** (§29.6 offboarding) and membership (§29.5).
- Citas that populate feeds come from **FR-17** (§27b.2); jornadas from **PRD-30**.
- Exports/reporting plots relate to **PRD-32** (§23.6 Informes).

## Validation approach (future, on staging)

Subscribe a coordinator .ics in a test calendar; confirm scope, folio-only titles, fixed offset;
offboard the membership and confirm the feed stops. Paste a Meet link into a cita. Import a small test
Sheet as a partera directory. Confirm Drive writes are refused without the sharing gate. Never validate
on production.
