# PRD-31 — Programas (the funded layer above jornadas, with seasonal feasibility)

- **Type:** PRD
- **Tier:** 2 — Roadmap (PRD v3 Part IV)
- **Priority:** P2
- **Status:** Backlog
- **Source:** PRD v3 **§21b**. Vocabulary: §18. Partners: ASOREDIPARCHOCÓ's *plan de respuesta a 12
  meses* and Herencia's *Timbiquí Suena* are programas (§30, §31). Sequence: §33 step 6.

## Problem / why

A jornada is one occurrence. **What an organisation plans and funds is a programa**: an objective, a
target population, a cadence, a budget, and the set of jornadas that realise it over months (PRD v3
§21b). ASOREDIPARCHOCÓ's twelve-month plan and Herencia's *Timbiquí Suena* are programas; neither is a
shipment and neither fits in a jornada. A programa **cannot be the container in the navigation** (an
emergency shipment belongs to no programa) — so it lives inside **Agenda** (§18).

## Scope

**In:**
- A **programa** entity holding: Objetivo · Población objetivo · Cadencia (monthly brigade / twelve
  weekly sessions / quarterly delivery / one-off) · Duración (start, end, renews?) · Presupuesto
  (comprometido · aplicado · restante, **per programa**) · Financiador (who funds, what they need
  reported) · Indicadores (coverage, attendance, delivery, completion) · Jornadas (planned & actual).
- **Seasonal feasibility across a year (§21b.2) — the differentiated capability.** Using Rutas'
  travel time **and cost by season** (already stored), answer at planning time: *which months is each
  community actually reachable, and what does the year cost?* Return a calendar with reachability per
  month, cost per month, and the gaps **named**:
  > «Docampadó queda incomunicada de junio a octubre — la jornada de agosto no la alcanza.»
  > «En seca, Bellavista → Beté pasa de 165 a 215 minutos y de $420.000 a $480.000. El costo del
  > segundo semestre sube 14%.»
- **Persistent rosters (§21b.3):** `taller`/`formacion` carry **participants that persist across
  jornadas** — the first thing in Convite that tracks the same people across events. Attendance is per
  session; completion is per cohort. The §22 rule still binds: **record that someone attended, never
  what for.**
- **Programa-level sponsorship (§21b.4):** apadrinamientos can fund a **programa**, not just a
  beneficiary — «financia el banco de medicamentos por seis meses». Same consent rules (label, never a
  name). Programa totals mirror Apadrinar: comprometido · aplicado · disponible (enriches PRD-12).
- **Planning flow (§21b.5):** select communities on the map (§23.5) → fix cadence + duration → system
  returns the calendar (reachability + cost per month) → names the inviable before anyone promises it
  → generates **draft** jornadas → each confirmed separately, with a name. Plans diverge: a jornada
  that happens differently is **edited, not deleted**; the programa shows planned vs actual (what a
  funder report needs).

**Out:**
- The jornada entity itself — **PRD-30** (§22).
- The map selection surface that seeds a programa — **PRD-32** (§23.5).
- Content/curriculum delivery (theirs, §2, §31).

## Acceptance criteria

1. A programa can be created with objective, target population, cadence, duración, budget, financiador,
   indicators, and a set of jornadas.
2. Budget tracks **comprometido / aplicado / restante per programa**.
3. Given selected communities + cadence + duration, the system returns a **twelve-month calendar** of
   reachability and cost **by season**, and **names** the months a community is unreachable — never
   fabricating future state beyond seasonality (a route closed by a verified damage report stays
   closed and is flagged; we do not guess when it reopens).
4. `taller`/`formacion` programas carry a **persistent roster**; attendance is per session, completion
   per cohort; no record of what any attendee needed.
5. A sponsorship can fund a **programa**; programa-level comprometido/aplicado/disponible totals show;
   sponsor sees a label + programa, never a name.
6. Draft jornadas generated by the planning flow are **confirmed individually**; a diverging jornada is
   edited and the programa shows planned vs actual.

## Dependencies

- **Contains** PRD-30 (jornadas). **Consumes** PRD-32 (§23.5 map selection) for the planning flow.
- **Seasonal feasibility** relies on Rutas seasonal rows (built, §9) — verify the cost-by-season data.
- **Enriches** PRD-12 (Apadrinar → programa funding). **Coverage indicators** consume PRD-29
  (assessments §21). Region scoping via **PRD-37**.

## Validation approach (future, on staging)

Create a programa, select communities, set a monthly cadence for a year, and confirm the calendar
returns reachability + cost per month with unreachable months named; fund the programa via a
sponsorship and confirm programa totals + label-only privacy; run a `formacion` and confirm the roster
persists across sessions with attendance-only records. Never validate on production.
